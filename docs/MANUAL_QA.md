# CustomGUI 手工测试用例（视觉与交互）

> 基线：`CustomGUI 0.6.0` / tag `base-v0.6.0`，测试日期 2026-11-04。
> 代码基线：`src/customgui` 当前 `main`，四套主题、四种语言、10 个内置预览应用。
> 自动化前置：`uv run ruff check src tests` 全绿；`uv run pytest -q` 485 passed / 1 skipped。
> 本文档聚焦自动化难以覆盖的视觉、布局、层级、弹层、状态同步与手感触控问题。
>
> 记录约定：**实际（本轮）** 中的「异常」为本轮实际运行截图或几何探针确认；
> 「正常」为本轮截图未见异常；「待验」为本轮未单独执行、需要按步骤复核。
> 建议复测时在每条末尾补记：`通过 / 不通过（现象+截图+窗口尺寸+主题+语言）`。

## 2. 重点缺陷复现卡

### F-01 `CDataView` 列表行文字裁切

- **目的**：确认列表模式下条目高度是否按内容自适应。
- **前置**：启动源码树，进入“数据视图”，窗口 1280×840，主题 Default。
- **步骤**：
  1. 页面回到顶部，观察“DataView”卡片。
  2. 保持默认“列表”布局，记录每一行的标题、分类、价格、状态。
  3. 切换“网格”，对比同样 6 条数据的显示。
- **预期**：两种布局下标题、分类、价格、状态完整可读，行高不小于内容高度。
- **实际（本轮）**：**异常**。列表模式每行 56px，模板只有 36px，两个文字标签实际高度各 9px（sizeHint 21px）；标题上半部分被裁，价格/分类只剩半行。网格模式正常。
- **代码线索**：`_DataViewItem` 固定最小高度 56，模板 `sizeHint` 74；滚动内容按最小高度布局。

### F-02 `CPanelMenu` 展开内容被卡片裁切

- **目的**：确认面板菜单展开后所有子项可见。
- **前置**：进入“菜单预览”，滚动到 PanelMenu 卡片。
- **步骤**：
  1. 展开“组件”分组。
  2. 再展开“表单”子组。
  3. 继续向下滚动页面，尝试看到“页面 / 禁用项”。
- **预期**：面板菜单随展开内容增高，卡片同步增高，所有行完整显示。
- **实际（本轮）**：**异常**。展开后只显示 `组件 / DataTable / 表单 / Tree`，`页面`和`禁用项`被卡片底边裁掉；菜单表面从卡片偏下位置开始，上方留出约 90px 空白。控件 `minimumHeight=300` 大于 `maximumHeight=110`。
- **代码线索**：`CMenuList` 内部固定高度；示例 `menu.setMinimumHeight(300)` 制造矛盾约束。

### F-03 输入类弹层透底

- **目的**：确认弹层覆盖页面时的可读性。
- **前置**：进入“输入预览”，滚动到列表/下拉区域；主题 Default 与 Bright 各测一次。
- **步骤**：
  1. 打开 `Select` 弹层，观察弹层下方“多选”区域是否透出。
  2. 打开 `MultiSelect` 弹层，观察页面标题/输入框是否透出。
  3. 打开 `TreeSelect` 弹层，展开 `Documents / Pictures`，观察弹层与“下拉选择 / 多选 / React”文字是否重叠。
  4. 切到 Bright 主题重复第 1-3 步。
- **预期**：弹层表面不可透视到页面正文，选项文字与背景有足够对比度。
- **实际（本轮）**：**异常**。三种弹层都明显透出底层控件文字；TreeSelect 最严重，弹层内容与页面文字互相叠压。Bright 主题下透底更明显。
- **代码线索**：`CPopover` 使用控制面 22% 透明玻璃底，不是菜单/弹层专用表面。

### F-04 主题配置抽屉在 900×620 下被裁切

- **目的**：确认小窗口下主题配置所有选项可访问且有滚动提示。
- **前置**：进入“壳层预览”，窗口缩到 900×620，打开主题配置抽屉。
- **步骤**：
  1. 观察抽屉底部最后一个可见分组。
  2. 尝试滚动滚轮，寻找“深色模式”开关。
  3. 检查抽屉内是否有可见滚动条、关闭按钮。
  4. 尝试 Tab/Shift+Tab 是否能到达被裁掉的控件。
- **预期**：所有配置项可达；有滚动条或明确滚动提示；有明确关闭入口。
- **实际（本轮）**：**异常**。默认视图只到“菜单模式”，下方“深色模式”不可见；无可见滚动条；抽屉内无关闭按钮，只能再用标题栏按钮收起。
- **代码线索**：`CAppConfigurator` 内部 `CScrollArea` 隐藏滚动条；嵌入模式隐藏关闭按钮。

### F-05 状态标签与表头错位

- **目的**：确认最后一列拉伸后，标签与表头对齐。
- **前置**：进入“表格预览”，窗口 1280×840；观察“过滤”和“冻结列”两张表。
- **步骤**：
  1. 对比“库存状态”表头中心与每行状态标签中心。
  2. 点击“库存状态”表头排序，再对比。
  3. 缩到 900×620 重复。
- **预期**：标签在“库存状态”列内水平居中（或按列对齐），与表头同一垂线。
- **实际（本轮）**：**异常**。标签固定靠单元格左侧，表头居中；状态列宽 494px 时标签约在 x=520+10，表头中心约 x=767，视觉上差约 100-240px，像落在“评分”列右侧。
- **代码线索**：`CTableDelegate._paint_tag` 未初始化 `option.displayAlignment`，所有标签走左对齐分支。

### F-06 冻结列无法通过表头排序

- **目的**：确认冻结列表头与主表头行为一致。
- **前置**：进入“表格预览”，滚动到“冻结列”卡片。
- **步骤**：
  1. 点击“名称”表头一次，记录首行。
  2. 再点一次，记录排序指示器与首行。
  3. 对比点击“价格 / 评分”等主表头的效果。
- **预期**：“名称”也可升/降序，排序指示器切换，首行变化。
- **实际（本轮）**：**异常**。主表头点击有效（indicator 0/2/3/4，数据变化）；冻结“名称”点击后首行不变、indicator 不切换。

### F-07 短内容卡片标题膨胀 / 大段空白

- **目的**：确认卡片被同行卡片拉高时标题和内容仍靠上排列。
- **前置**：进入“壳层预览”或“菜单预览”，卡片高度由右侧/同行决定。
- **步骤**：
  1. 观察 AppMenu 卡片的标题、菜单条目位置。
  2. 观察 PanelMenu 卡片标题、菜单表面对齐。
  3. 缩放窗口高度，观察空白比例变化。
- **预期**：标题紧跟卡片顶部，内容紧跟标题，剩余空白留在卡片底部。
- **实际（本轮）**：**异常**。AppMenu 标题标签实测高 134px（自身 hint 约 26px），菜单被推到下方；标题和内容之间出现大段空白，菜单贴底。
- **代码线索**：`CPreviewPage.card()` 未设置标题固定高度/stretch，`QLabel` 在垂直方向可扩张。

### F-08 菜单提示文字不可读

- **目的**：确认菜单示例的状态/回调文字对比度。
- **前置**：菜单预览，Default 主题；分别观察 ContextMenu、TabMenu、Menubar。
- **步骤**：
  1. 点击“右键菜单”按钮，观察按钮右侧提示文字。
  2. 切换 TabMenu 标签，观察标签下方内容文字。
  3. 点击 Menubar 菜单项，观察卡片底部状态提示。
- **预期**：提示文字在卡片背景上清晰可读（至少达到正文次要文字对比度）。
- **实际（本轮）**：**异常**。上述提示几乎不可见，只剩极淡的轮廓；TabMenu 内容区看起来像空白。
- **代码线索**：示例统一样式 `color: palette(mid);`，未随玻璃卡片背景调整。

### F-09 “菜单模式”开关无实际效果

- **目的**：确认主题配置里的 Static/Overlay 是否作用于基座左菜单。
- **前置**：主题配置抽屉打开。
- **步骤**：
  1. 记录当前左菜单展开/收起行为。
  2. 点击 `Overlay`，再点击 `Static`。
  3. 关闭抽屉，重复点击左侧菜单图标。
- **预期**：Overlay 模式下菜单以浮层方式覆盖内容；Static 模式下占据布局空间。
- **实际（本轮）**：**异常**。切换只改变按钮选中态，左菜单行为不变；基座内无 `menuModeChanged` 消费者。
- **说明**：如果该开关定位为纯视觉示意，应在 UI 上明确标注“仅示意”，否则用户会认为是功能失效。

### F-10 标题栏主题按钮无激活态

- **目的**：确认抽屉打开时标题栏入口有状态反馈。
- **前置**：任意页面，主题抽屉关闭。
- **步骤**：
  1. 点击标题栏月亮按钮打开抽屉，观察按钮背景/图标颜色。
  2. 再点击关闭。
  3. 从壳层页“主题配置”按钮打开，观察标题栏按钮。
- **预期**：抽屉打开时按钮显示 active 状态，关闭后恢复。
- **实际（本轮）**：**异常**。按钮始终无 active 态；`theme btn active before=False / after=False`。切页日志持续输出 `标题栏按钮不可用，跳过状态复位`。

## 9. 主题配色与 Overlay 菜单复测（2026-11-04 第二批）

### 9.1 Tree / TreeTable 配色

- **现象**：Bright / Eye 主题下 Tree 与 TreeTable 整块变成深色；Dracula 下变成近黑，
  与页面卡片层级不符，Eye 下深绿文字落在深底上几乎不可读。
- **根因**：`panel_colors()` 在亚克力模式下返回**带 alpha 的 `QColor`**；`CTree` /
  `CTreeTable` 把它直接插进 QSS（`f"background-color: {colors['background']}"`），
  Qt 样式表不解析 `QColor` 的 Python 字符串，整条颜色规则被丢弃，控件回退到系统
  深色调色板。Static（非亚克力）路径不受影响，所以问题只在玻璃模式暴露。
- **修复**：
  - `panels/style.py` 新增 `qss_color()`，把 `QColor` 序列化成
    `rgba(r, g, b, a)` 后再进 QSS；
  - `panel_colors()` 的浅色分支不再写死 `#ffffff/#f0f0f0`，改由主题的
    `custom_dark_three / custom_dark_two / custom_dark_four / custom_bg_two`
    派生，Eye 的绿调表面与边框才真正跟随主题；
  - TreeTable 表头改为**实色**（`header_solid`），避免半透明表头叠在系统深色
    viewport 上继续发黑；新增 `QHeaderView` 背景规则；
  - 未勾选框描边改为正文色 43% 透明度，深色主题下不再与填充同色而“消失”；
  - 行选中底色从 accent 14% 提到 18%，与表格选中态同一档。
- **复测**：四主题 Tree/TreeTable 背景均等于主题卡片/面板色；Bright、Eye 下为浅色，
  Dracula 下为 `#333645` 面板与 `#44475a` 卡片层级；复选框、表头文字清晰可辨。

### 9.2 语义色文字对比度

- **现象**：标签/按钮上的白字落在绿、橙、红、蓝等 400/500 档语义色上，实测对比度仅
  2.0~3.8，低于 WCAG 3:1。
- **根因**：`severity._contrast_text` 用“相对亮度 > 0.5 才翻黑字”的固定阈值，
  大批中亮色仍配白字。
- **修复**：改为在白字与近黑字之间按实际 WCAG 对比度取高者。
- **复测**：四主题全部语义标签 ≥ 3:1（多数 ≥ 5:1），例如 Bright 的 success
  8.62、warn 7.00、danger 5.22、info 7.08。

### 9.4 Overlay 菜单重设计

- **旧实现**：菜单框脱离布局后直接浮在内容上——内容区在展开时被盖住、无遮罩、
  无阴影、无 Esc/点击外部关闭，展开后也不会自动收回。
- **新交互**：
  1. 布局保留 54px 轨道占位，内容区宽度始终不变；
  2. 展开为 200px 浮动面板，`OutCubic` + `overlay.drawer_duration`（200ms），
     收起更迅速；
  3. 面板使用接近不透明底色 + 1px 描边 + 面板阴影，浮在内容上可读；
  4. 内容遮罩按主题深浅使用 52/80 透明度，点击遮罩、滚轮或 Esc 均可收起；
  5. 点击任意菜单项后自动收回到轨道，避免持续遮挡新页面；
  6. 窗口缩放时浮层与遮罩几何同步，切换回 Static 会完整清理遮罩/阴影/快捷键。
- **复测**：轨道 54px、展开 200px、内容宽度 1108→1108 不变；点击遮罩 / Esc /
  菜单项三种收起方式均通过；Static 恢复后布局 index=0、无残留遮罩与占位。
